# ADR 0008: Fresh Source Snapshots Stay Separate From Context Evolution

## Status

Accepted for MVP implementation.

## Context

An Agent launched from a long-lived or dirty workspace can answer a read-only
question from stale code while presenting the result as current. A local
remote-tracking ref is not proof of the live remote ref, and updating it inside
the user's repository changes repository metadata even when the task otherwise
claims to be read-only.

Agent Context Patch already governs reusable Agent context, but `$evolve` runs
after a verified correction. Source freshness is a pre-task provenance concern
and must not be coupled to the proposal, Commit Kernel, or context-write
lifecycle.

## Decision

The Kit ships a separate `source-snapshot` Skill and deterministic Node runtime.
Its initial public source mode accepts a repository, remote, and exact full Git
ref. It:

1. resolves the ref with `git ls-remote`;
2. fetches it into a bare cache outside the workspace;
3. requires the observed and fetched commit identities to match;
4. materializes the pinned tree from raw Git blob objects into a task-owned
   temporary directory, bypassing checkout and archive line-ending filters;
5. rejects incomplete submodule snapshots and symlinks escaping that directory;
6. makes the extracted tree read-only and records an integrity digest; and
7. removes only task-owned state after an unchanged close.

The canonical Skill lives at `skills/source-snapshot`. The Claude marketplace
plugin contains a generated byte-identical distribution tree, and release/tests
fail if it drifts from the canonical tree. This is distribution duplication,
not a second implementation.

Receipts are ephemeral task evidence. They do not enter `.agent-context/` and
do not become evolution proposals merely because a task ran. A repeated or
corrected workflow failure may still trigger the ordinary post-verification
evolution checkpoint.

## Consequences

- Read-only means the project repository and working tree remain unchanged;
  the external cache and temporary session are writable runtime state.
- Network or ref instability fails closed. Cached or local source cannot be
  called latest without a successful freshness proof.
- Builds, dependency installation, generators, and tests remain outside this
  mode and require a separately isolated verification environment.
- Provider-specific deployed-revision resolution and Git submodule
  materialization remain future adapters, not implicit behavior.
- The current single-Skill Bootstrap is not silently widened into a multi-Skill
  upgrade transaction. General Agent installation must gain an explicit,
  reviewed companion-Skill plan before Source Snapshot is claimed as installed
  outside the marketplace plugin.

## Verification

Acceptance tests use local bare remotes and isolated temporary directories.
They cover a stale local remote-tracking ref, dirty primary checkout, generic
PR-style ref, remote failure, concurrent cache access, escaping symlink,
credential-bearing remote rejection, changed-snapshot retention, safe close,
submodule fail-closed behavior, byte identity, nested directories, and long
paths.
