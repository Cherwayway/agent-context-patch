# Domain Pack: PRD

Use this pack for product requirements, specs, user stories, acceptance
criteria, and planning documents.

## Triggers

- User says the requirement was misunderstood.
- Agent missed a constraint, persona, platform, or rollout boundary.
- PRD lacks acceptance criteria.
- Agent mixed discovery with approved implementation.
- Project repeatedly needs the same requirement template.

## Checks

- Is the source requirement explicit and current?
- Are users, goals, non-goals, constraints, acceptance criteria, and risks
  present?
- Are unknowns marked as unknown instead of facts?
- Are downstream engineering/design/data dependencies clear?
- Does the PRD separate candidate ideas from approved scope?

## Evidence Examples

- User correction about target user or non-goal.
- Missing acceptance criteria in an approved spec.
- Conflict between product doc and implementation plan.

## What Not To Memorize

- Brainstorm ideas not accepted by the user.
- One-off launch copy.
- Unverified market assumptions.
- Temporary prioritization that has expired.

## Cleanup Rules

Archive context that describes old product positioning, deprecated personas, or
rejected feature directions.
