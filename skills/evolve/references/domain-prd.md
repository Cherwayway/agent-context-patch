# Domain Pack: PRD

Use for product requirements, specs, user stories, acceptance criteria, and
implementation planning.

## Detection Guidance

Candidate evidence includes an active PRD/spec directory, approved requirement
documents, product templates, or recurring acceptance-criteria work. A single
historical brief is weak evidence.

## Checks

- Identify the current requirement source and approval state.
- Separate goals, non-goals, users, constraints, and acceptance criteria.
- Mark unknowns as unknown.
- Expose design, engineering, data, and rollout dependencies.
- Separate candidate ideas from approved scope.

## Evidence Examples

- user correction to an approved target user or non-goal
- missing acceptance criteria in the current spec
- conflict between an approved product source and implementation plan

## What Not To Memorize

- unapproved brainstorm ideas
- one-off launch copy
- unverified market assumptions
- expired temporary priority

## Cleanup Rules

Propose cleanup for rejected directions, deprecated personas, obsolete
positioning, and requirements superseded by a current approved source.

## Materialized Checklist

- Identify the source requirement and approval state.
- Separate goals from non-goals.
- Define users, workflow, constraints, and acceptance criteria.
- Mark unknowns and dependencies explicitly.
- Keep candidate ideas separate from approved scope.
